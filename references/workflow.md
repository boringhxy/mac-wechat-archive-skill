# 操作细节

每一步只支持本次证据范围内的结论。流程目标是保存本地文件并尝试限定环境下的读取检查，不是保证找回所有历史或提供通用导入。

## 1. 只读建立事实

确认目标、授权、用户角色和允许位置。发现实际安装的微信/版本和当前系统用户，探测真实数据路径；不能把某版本常见目录当作本机事实。不读取无关聊天正文或凭证。

记录源类型及本次身份、已存在归档、工作映像、布局、既有检查对应的快照和环境。原路径可能不存在、含新数据、是符号链接或已挂载卷；未知状态先查明，不强行覆盖或卸载。

只对确认的微信范围查容量、占用和进程。按[硬盘条件](storage-conditions.md)分开查宿主卷、映像内部与内置盘的读写和容量，记录真实格式、连接及未知项。内置盘不足时，不在内置盘再复制同样体积，也不创建系统账户来声称获得新空间。

## 2. 文件存档与差异

先复用已有产物，核对身份、格式、清单、报告和是否在之后发生变化。盘点不是SHA核验；历史通过也不自动证明当前产物未变。针对实际不确定性做必要检查，不每一步都无理由重新读满或导出整套。

在微信退出后采集稳定快照，记录已枚举根和排除项。每个已枚举路径记录类型、长度、内容SHA及链接关系，另存可读取元数据、权限、时间、扩展属性、ACL和标志。读取错误、源变化和未捕获的依赖明确报告；集合覆盖一致只针对这个枚举范围。

比较复制前后源状态；普通读取导致的atime变化不当作新消息。归档路径不许绝对路径或`..`穿越；不沿源链接递归，也不沿目标链接写出卷外。

完整大小的中断文件不等于内容正确。可复用已确认部分，但最终必须核对所声称覆盖的内容；部分文件只在前缀验证匹配后补写。归档截尾或xattr错误不能当作成功，修复仅限可证明的结构与条目，保留错误及原产物。

新增变化保存为小量增量、最新路径集合和元数据，说明内容由哪些旧归档或增量提供。清单“删除”只描述快照变化，不实际删除源或旧产物。不能将增量在隐藏目录中保存，称作供微信使用的最新视图已形成。

## 3. 工作映像与指定视图

外盘文件系统不能保存所需Mac语义时，可在盘上使用Mac格式的读写映像；不格式化物理盘。是否新建、格式与容量按实测环境和净新增空间决定，不默认新增完整副本，不把一次稀疏映像失败写成普遍限制。

明确映像内的路径映射，区分活动微信数据、非活动辅助归档和回退材料。辅助目录仅“被保存”不表示已经替换本机实际配套目录；原生样本检查可能依赖后者，须记录。

应用指定清单前：

1. 算清净新增写入：新活动载荷、新旧需并存而新增的版本、元数据/日志和文件系统余量。现有分配不重复计入；必须保留的数据不能当作可回收空间。不足时停在修改前，不另做整套副本来绕过。
2. 保存被改路径的旧版本、元数据和自描述原路径日志。保留测试新数据；不能直接覆盖数据库来合并不同时间线。
3. 仅写入确定的变化，复制来源必须与对应清单内容匹配。避免每个小项重复创建整套深层目录；日志要可从实际目录重建，不以反复重做替代接续。
4. 枚举活动路径中的清单外项，尤其数据库WAL/SHM和测试新增媒体。未知项先停止并解释版本关系；已判定旧测试项保留后移出活动路径。仅确认不映射到任何活动路径的隐藏旧缓存可原位保留，并单独记录，不套用于聊天文件。
5. 核对指定视图的文件内容、目录、链接和额外项。硬链接可按本次文件身份复用读取结果，但每个逻辑路径都须覆盖。物理读取量不等于逻辑总量。
6. 记录可保存/可应用与未应用的元数据，工作副本必要临时写权限在完成后恢复；不强加压缩、不可变等系统标志来追求“原样”。

完成后只能称“工作文件视图与指定清单相符”，不能据此称会话已恢复。用户打开微信后该副本可能改变，记录其检查前后版本。

## 4. 临时读取事务

前提：本次明确授权原生检查、必要文件检查通过、未知活动项已解决、微信无写入进程、回退路径与容量可用。仅备份授权不自动包含切换。技术步骤已在明确授权内时，不重复索取同一确认。

先持久化本次初始状态、映像身份、挂载点、源设备/inode、唯一保留位置与反向步骤：

- 原目录存在：确认是本次普通目标目录，在同父目录只改名保留，保护新消息，不复制整套或合并旧库。
- 原目录不存在：记录初始不存在，只创建必要空挂载点；不要求虚构的原件数据库或旧inode存在。
- 新目录已出现：捕获它的新身份；不能套历史hold_path、inode或旧脚本前提。
- 符号链接/未知卷/不明身份：先查明，不叠加替换。

核实微信退出后正常卸载暂存卷，再将准确映像挂到正式点。核对映像身份、文件系统、预期数据库和设备关系。原目录存在时比较保留目录设备；不存在时比较正式点父目录所在内盘设备。

失败尝试本次回退。回退失败说明实际位置与错误，停止叠加操作，不承诺任何失败都自动保证不丢。不得强制卸载未知卷或改安全策略使挂载通过。

## 5. 原生样本检查

由用户登录/扫码、确认账号，检查备份快照范围内指定的文字、已下载原图及可播放视频，必要时跨日期抽样。缩略图不足。手机独有、从未到电脑或未本地下载的内容不在文件枚举已保存的证明内。

记录实际挂载范围、仍使用的本机配套配置和账号环境，以及网络/缓存/媒体来源状态；不能确认来源时写未知，不断言所有显示内容来自备份。不得以句柄或进程运行替代用户检查。

用户确认后报告“这些样本在该环境中当时可读”。不称所有消息完整、独立恢复、未来可恢复或跨机保证。原图视频能显示也不证明整套媒体已逐项验收。

## 6. 回退

用户实际退出后再实查写入进程、映像身份，正常卸载。将空挂载点另行改名保留，恢复本次保留目录；初始不存在则恢复不存在。保留工作映像中的测试新数据，原生写入后的内容不与检查前哈希混称同一状态。

核对本次源身份或初始不存在状态、映像未附加和产物位置。不要把历史已删除源找不到当作故障，不能覆盖后来新数据。

## 7. 用户手动清理与推出

**清理前当次复核是给出删除步骤的前提。** 包括只接续“最后清理”的任务：在给出任何移入废纸篓或永久删除步骤前，只读实查并记录下列条件，不能只引用上次的通过报告：

1. 微信及本任务涉及的写入进程当前已退出；用户说已退出后仍需实查。
2. 临时映像已解除附加，原路径不再被其占用。本次发生过切换时，回退核对当前仍成立；从未切换则记录回退“不适用”，不额外创建一次挂载来凑齐步骤。
3. 唯一目标是本次确认的内置盘微信原件：实际路径、目录类型、设备/卷及本次身份相符，目标与父路径无未解决的链接或挂载歧义。路径名或“普通目录”不足以证明在内置盘，不能指向外盘工作副本或存档。原件已不存在则报告事实，不另找相似目录代删。
4. 拟清理范围可对应到已保存并通过所声称范围内容核验的快照；未解决的校验失败、读取错误或覆盖范围不明均阻断。核验之后的新增/变化已查明，必要差异已保存并核验。可复用仍有依据的旧核验，不无理由重读全量或再做整套副本；不能用旧样本可读代替新记录的保存证据。

任一条件失败或未知，保留原件和已有产物，只说明阻断点及必要下一步，不给删除步骤。解决问题仅在本次授权内推进；只读授权不能变成回退、复制或修复授权，用户自行执行删除也不豁免上述条件。记录本次检查时间、证据与唯一目标；检查后重新运行微信、重新挂载、路径变化或出现新数据时，原结论不再用于后续删除指导，只复核受影响条件。

条件满足后说明证据和剩余限制：文件核验及样本可读不能保证未来全部原会话可读；删除本地原件会失去这个本地回退来源。用户决定后给唯一已核实目标，不要求重复同一授权或风险确认。

用户保持微信退出，自行将该目标移入废纸篓，再仅永久删除刚移入的这一项，不清空整个废纸篓。移入后需能确认与原目标是同一项；无法确认时停止永久删除指导，不读取其他废纸篓项目，按系统允许的已知目标核对或由用户仅对该项放回。说明删除整个本地历史与仅删除某日期以前不同，不能靠文件时间粗删附件维持会话关系。

用户报告完成后只读核对已知路径、实际空闲及与基线变化。不读其他废纸篓资料，不把du量承诺为释放量；删除失败可能已部分完成，本地剩余源不能覆盖可信归档。

推出前核对本任务映像和可见占用，由系统正常推出。未发现占用不代替系统判断，图标消失再拔线，忙碌时不强制卸载。完成本次电脑范围就结束，手机另行请求。
