# Mac WeChat Archive Workflow

> **声明：本项目内容为纯 AI 生成，仅供参考。**

面向 macOS 微信**本地文件存档与读取核验**的说明型 Agent Skill，名称为 `mac-wechat-archive`。

## 它能协助什么

- 检查本地数据位置、已有归档、容量、任务进程和挂载状态。
- 按当前系统、微信版本、数据布局及存储能力选择流程；记录历史样本、待验证项和本次阻断点。
- 为已枚举的本地文件建立清单、校验内容、保留差异及接续记录。
- 在本次授权、环境条件和文件检查允许时，尝试临时读取工作副本，并在退出微信后核对回退结果。
- 记录用户对指定会话、原图和视频的样本检查，准备由用户本人执行的单项清理步骤。

这是操作指导，不包含微信数据、解密工具或一键导入/删除脚本，也不是腾讯官方备份或恢复产品。

## 不能据此承诺什么

**不保证全部消息和附件百分之百回到原会话，也不保证未来或另一台机器仍能读取。**

| 证据 | 仅能支持的结论 |
|---|---|
| 归档整体SHA匹配 | 该归档字节与记录值匹配 |
| 已枚举文件逐项SHA匹配 | 指定路径集合的内容与指定快照匹配 |
| 用户在微信中看到了样本 | 记录的环境、时间及依赖下，这些样本当时可读 |
| 路径与设备检查通过 | 本次挂载或回退的路径关系符合记录 |
| 用户删除后空闲空间实测 | 测量时的可用容量及相对基线变化 |

这些证据不证明源数据库本来没有缺失、全部历史已在这台电脑下载、所有附件均由备份提供，或所有账号/系统依赖已被保存。原生检查可能仍依赖本机配置、登录上下文、未替换的数据目录或网络；依赖没有排除，就不能称为“备份独立恢复成功”。

验证结果只对应所记录的快照和环境。微信运行会修改工作副本；同机后续重新登录、升级或配置变化，也不能直接沿用旧结论。

## 工作边界

只处理本次明确授权的微信目标和任务产物。保护现有新消息、原始归档及测试期间产生的数据，优先复用已有产物，不默认再做整套副本。

删除、清理及废纸篓永久删除由用户本人执行。清理前说明已知证据和未验证范围：删除本地原件意味着失去该本地回退来源，已有检查不构成未来百分之百可恢复的保证。

给出清理步骤前必须当次核对微信退出、临时挂载撤回与所需回退、内置盘唯一目标身份，以及拟清理范围和新增变化的保存核验证据；任一项失败或未知就停止给出删除步骤，旧报告不代替当前状态。详见[清理前复核](references/workflow.md#7-用户手动清理与推出)。

不格式化物理盘，不改其他应用或普通文档，不打包钥匙串、索要密码、重签微信或关闭系统安全机制。只读授权不升级为目录切换、解锁或改权限。手机工作另行明确范围。

## 按环境选择流程

这是供AI执行者使用的检测与决策指导，不包含自动转换微信数据库的程序，也不将尚未测试的环境列为已支持。源快照与当前读取端的版本、构建、架构、实际数据布局和存储条件分别记录；历史记录与当前条件不混为一谈。

| 状态 | 意义及下一步 |
|---|---|
| 已有样本记录 | 仅有指定环境、时间与样本的可读证据；仍需核对当前前提，字段不全时保留缺口 |
| 待验证 | 默认只读盘点；已授权文件归档可继续，但不自动切换。已授权受控检查且前提具备时，可逐步验证，不要求预先成功过 |
| 条件不满足 | 当前空间、读写、布局、身份或回退有阻断，停止受影响操作，保留现状；不直接判永久版本不兼容 |

外盘均为exFAT时，仍分别验证“宿主exFAT → 普通读写DMG → 内部APFS”。只有授权允许时才在独立空任务路径做小型映像探针，不触碰微信原路径。探针通过后还要核对布局、文件视图、回退准备，再在授权内尝试原生样本；没有现成成功记录不等于永远不能尝试。

“已有样本记录”不是删除许可。为保留原会话读取能力而清理时，未知组合缺所需原生证据或当前回退未完成，均不给删除指引；单纯文件归档任务在文件结果处结束。完整条件见[环境检测与流程选择](references/compatibility.md)。

## 硬盘与环境条件

开始前必须实查，不能只看标称容量或盘名：

| 项目 | 条件与边界 |
|---|---|
| 外置卷 | 当前可稳定识别、读写，单文件大小限制能容纳计划产物；不是只读、掉线或I/O报错状态 |
| 文件系统 | 需要Mac元数据时，应验证目标本身或其内部映像能保存所需语义；exFAT可作为映像文件的宿主，不等于其目录直接具备APFS语义 |
| 外盘空间 | 分别计算新归档、映像外部新增分配、日志和临时峰值；已有产物不重复计入，不足则停止写入 |
| 映像内部空间 | 另算活动文件更新、必要新旧并存、元数据/回退记录及余量；外盘有空间不代表映像内部有空间 |
| 内置盘空间 | 仍需容纳私有清单、日志、必要临时文件及系统运行；不在快满的内置盘再解压整套数据 |
| 连接与使用 | 使用工作映像期间保持连接；退出微信并完成卸载后正常推出，不强制拔盘 |
| 性能 | 机械硬盘或较慢连接处理大量小文件、属性和全量读回可能较慢；不承诺固定完成时间 |

不要求固定容量、品牌或映像大小。同一块盘上的归档和映像是两个文件产物，**不是两块独立介质的冗余**，不以多复制同盘文件来声称消除介质失效风险。

不同微信版本、系统环境和存储格式不能直接沿用同一个兼容结论。下面的单次样本记录不构成支持列表；每次仍须核对当前宿主卷、映像、属性及原生读取条件。本仓库没有提供公开可复现的硬件/版本兼容矩阵；具体型号、固件、接口或健康状态若未测量，就不声称验证过。

详细容量计算、故障停止条件和需记录的环境项见[硬盘条件](references/storage-conditions.md)。满足这些条件仍不能推出原会话可恢复。

## 单次样本的版本与环境依据

这里的“跑通”仅指：**2026-11-09，在原 Mac、原系统用户与原微信账号上下文中，临时读取外盘工作映像时，用户确认了所检查的聊天、原图和视频样本当时可读。** 旧快照与较新记录分别有用户确认；未记录具体会话、日期范围或样本数量，不能解释为全量验收。用户曾反馈加载较慢。

| 架构 | **arm64** | 本次补充实查；不据此宣称 Intel Mac 已验证 |
| 外盘宿主卷 | **标称 2TB，exFAT** | 来自恢复任务历史记录；补查时外盘未连接，未重新检测格式、容量、接口或健康状态 |
| 工作映像 | **普通读写 UDIF / `.dmg`，逻辑容量 160GiB** | 来自历史创建与挂载记录；160GiB 是该次选择，不是最低容量要求，也不是聊天数据大小 |
| 映像内部 | **APFS** | 历史探针记录了读写、符号链接和扩展属性检查；该映像随后用于样本读取 |
| 临时读取范围 | **主聊天目录 `xwechat_files` 挂回微信原数据路径** | 其他配套归档不等于全部替换到本机原位置；仍可能使用本机配套配置和登录上下文 |

“磁盘条件”在这里主要指外盘文件系统、映像格式和映像内部文件系统三个层次，不能合并成一个“磁盘版本”。硬盘固件、exFAT/APFS 的具体格式修订号未记录，不补造版本值。硬盘品牌、容量或同一版本号相同，也不能代替当前实测。

本次记录的组合可概括为：**微信 4.1.13（269602）＋同机账号环境＋exFAT 外盘上的普通读写 DMG＋内部 APFS**。macOS 15.5 / arm64 是补查信息，不能独立证明历史测试全程处于该系统版本。稀疏映像曾在该环境的创建/挂载尝试中失败，因此不将稀疏格式列为本次成功路径，也不推定它在所有 Mac 上均不可用。

联网、媒体缓存和未替换配套目录的依赖没有全部排除，因而未验证所有显示内容均来自归档、离线独立恢复、跨机/跨账号/跨版本兼容性或未来可读性。历史证据由本地任务持有，不随公开仓库发布；上表是脱敏摘要，不是可独立复现的测试报告。

## 使用

将本仓库目录作为一个 skill 放到当前 Agent 支持的技能目录，或用该宿主提供的本地技能导入方式。不要把实际聊天数据、运行日志或个人配置放进这个公开仓库。

Codex调用示例：

```text
请使用 $mac-wechat-archive，只读核对我的微信文件位置与已有归档，说明目前有哪些证据、还有什么没有验证，不挂载、不改名、不删除。
```

```text
请使用 $mac-wechat-archive，尝试查看已归档的旧记录，保护当前新消息。先核对快照和环境；按本次授权做可回退的临时读取，检查结束后核对回退，删除由我本人执行。
```
